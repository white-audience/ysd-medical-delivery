## 四、每个阶段做了什么

### 阶段 0：注册进 Nacos

**做了什么：** 单体 `ysd-server` 注册到 Nacos。

**学习点：** 服务注册与发现原理、Nacos 与 Eureka 区别。

**踩坑：**
- **WSL/Docker 虚拟网卡 IP 导致 503** → 加 `spring.cloud.nacos.discovery.ip: 127.0.0.1` 解决
- **Nacos 3.x 强制要求 `NACOS_AUTH_TOKEN`**

### 阶段 1：抽网关

**做了什么：** 新建 `ysd-gateway`，所有请求先过网关。

**学习点：** Spring Cloud Gateway 路由、GlobalFilter、JWT 统一鉴权、身份透传（`X-Identity-Id`）。

**踩坑：**
- **依赖选错**：选成 Gateway MVC（Servlet 版），应选 Gateway WebFlux（Netty 版）
- **SCG 2025 构件改名**：`spring-cloud-starter-gateway` → `spring-cloud-starter-gateway-server-webflux`
- **`X-Identity-Id` 可伪造**：网关写入前必须先 `remove` 同名头
- **Gateway 4.3.0 配置前缀迁移**：`spring.cloud.gateway.routes` → `spring.cloud.gateway.server.webflux.routes`

### 阶段 2：剥离低耦合服务

**做了什么：** 拆出 `user-service` / `admin-service` / `report-service`。

**学习点：** 服务拆分流程、Mapper 副本策略（A1 方案）、`@AutoFill` 切面跨服务共享。

**踩坑：**
- **`@JsonIgnore` 加错位置**：登录 DTO 的 password 被屏蔽 → 改 `@JsonProperty(WRITE_ONLY)`
- **`report-service` 直读业务库**：技术债，阶段 5 用 CQRS 修

### 阶段 3：剥离 Catalog 服务

**做了什么：** 拆出 `catalog-service`（分类 + 药品 + 药品组合）。

**学习点：** 限界上下文、跨库 JOIN 的处理（字段冗余 vs Feign）。

**关键决策：**
- **三表一起拆**（有 JOIN，不拆开）
- **`ysd-server` 侧 Drug/DrugCombo Mapper 瘦身**（只留 `getById`）
- **不加 `category_name` 冗余**（因为三表同库，JOIN 合法）

### 阶段 4：剥离订单服务（最难）

**做了什么：** 拆出 `order-service`（订单 + 购物车 + WebSocket + 定时任务）。

**学习点：**
- **A1 方案的延伸**：只读 Mapper 直连库（阶段 5 用 Feign 还债）
- **WebSocket 多实例**：Redis Pub/Sub 广播（方案 4.7）
- **定时任务防重**：ShedLock + Redis
- **`WebSocketTask` 丢弃**（无业务含义的心跳）

**踩坑：**
- **`/user/shoppingCart/sub` 接口漏搬**（后补）
- **`drugId=1` 不存在**（数据问题，NPE）
- **`@Transient` 是 `java.beans.Transient`，不是 `@Transactional`**（阶段 4 修）

### 阶段 5.1：Feign 跨服务调用

**做了什么：** 新建 `ysd-api` 模块；4 个只读 Mapper 改成 Feign 调用。

**学习点：** Feign 声明式调用、`FeignRequestInterceptor` 上下文透传、`/inner/**` 内部接口隔离。

**踩坑：**
- **OpenFeign 4.x 配置前缀迁移**：`feign.client` → `spring.cloud.openfeign.client`
- **`loadbalancer` 需显式加**（starter 不一定传递带出）

### 阶段 5.2：MQ 解耦

**做了什么：** 新建 `ysd-push-service`；支付通知从"直接调 WebSocket"改成"发 RabbitMQ"。

**学习点：** MQ 解耦、fanout exchange + `AnonymousQueue`（广播 vs 竞争消费）、灰度切换。

**踩坑：**
- **WebSocket 多实例必须 fanout**（固定队列名会变竞争消费）
- **`spring-boot-starter-data-redis` 不能删**（ShedLock 依赖）

### 阶段 5.3：Sentinel 限流熔断

**做了什么：** 网关限流 + Feign 熔断降级 + 规则持久化 Nacos + Sentinel Dashboard。

**学习点：** Sentinel 网关限流、Feign 熔断降级（`fallbackFactory`）、规则持久化。

**踩坑（本阶段坑最多）：**
- **`grade: 0`（线程数）在网关下恒放行** → 必须用 `grade: 1`（QPS）
- **QPS 限流验证必须真并发**（顺序发不触发）
- **Dashboard `appType` 缓存**：`computeIfAbsent` 固化，首心跳为 0 就一直显示普通应用
- **Nacos 配置漂移**：第二个写入方反复改配置
- **Feign fallback 静默失效**：三前提缺一不可

### 阶段 5.4：缓存

**做了什么：** Catalog 缓存改造（9 个 Phase）。

**学习点：** 缓存穿透/击穿/雪崩的区别与防护、延迟双删、JSON 序列化坑。

**关键技术方案：**
| 项 | 内容 |
|---|---|
| **防穿透** | 空值缓存（空集合 + TTL 60~70s）|
| **防击穿** | 本地互斥锁（`ReentrantLock` + `ConcurrentHashMap`）|
| **防雪崩** | TTL + 随机偏移（drug 10~12min / drug_combo 15~18min / category 30~35min）|
| **延迟双删** | 事务提交后延时 500ms 再删缓存 |
| **JSON 序列化** | `GenericJackson2JsonRedisSerializer` + `JavaTimeModule` + `activateDefaultTyping` |

**踩坑：**
- **`Collections.emptyList()` 反序列化会崩**（包私有类）→ 用 `new ArrayList<>()`
- **`activateDefaultTyping` 必须自己加**（否则反序列化变 `LinkedHashMap`）
- **`updateWithSpec` 缺 `@Transactional`**（顺手修的真 Bug）

### 阶段 5.5：链路追踪

**做了什么：** 引入 Micrometer Tracing + Zipkin。

**学习点：** TraceID/SpanID 区别、traceId 跨服务传递、Sleuth → Micrometer Tracing 变迁。

**踩坑：**
- **必须加 `spring-boot-starter-actuator`**（不加则所有配置静默失效）
- **默认采样率 0.1**（本地要改 1.0）
- **`@SpringBootApplication` 扫描范围不够**：filter 在 `com.ysd.filter`，主类在 `com.ysd.ysdgateway` → filter 从未被 Spring 加载
- **网关缺 `ysd.jwt` 配置** → `userSecretKey = null` → NPE → 401

## 八、改造方法的经验总结

### 人机分工原则

| 谁做 | 做什么 |
|---|---|
| **你** | 决策（架构、拆分边界、技术选型）、排错、理解核心原理 |
| **Agent** | 体力活（代码搬运、配置生成）、检索、review |
| **绝不让 Agent 做** | 替你决策、替你排错、替你理解原理 |

### 每个阶段的固定流程

```
1. 扫描（Agent 出清单）
2. 决策（你拍板）
3. 执行（Agent 干，每个 Phase 编译验证）
4. 联调（你手动）
5. 总结（Agent 写 md）
6. git commit（你）
```

### 每个阶段都要有的三份文档

| 文档 | 内容 |
|---|---|
| `stage5-xxx-prep.md` | 扫描清单 + 风险点 + 决策问题 |
| `stage5-xxx-summary.md` | 做了什么 + 面试素材 + TODO |
| `stage5-xxx-pitfalls.md` | 踩过的坑 + 排查过程 + 面试讲法 |
