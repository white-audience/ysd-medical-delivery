# 药速达（ysd-take-out）→ Spring Cloud 微服务改造 · 操作手册

> ⚠️ **归档说明**：本文记录于微服务改造前期（2026-10）。改造已执行完毕，部分步骤已被后续架构取代（完成态为网关 + 7 条路由 + 7 个服务，含 AI 8088）；相关最新实现请参阅 `docs/02-架构设计与开发/微服务改造全记录.md`。文中提到的 `docs/09-项目记录/` 属内部阶段记录，不随开源仓库分发。

> 本手册是 [`微服务改造方案.md`](微服务改造方案.md)（**方案**：拆什么、为什么）的配套**操作版**（**谁做、按什么顺序做、每步怎么验收**）。
> 方案文档回答「拆成什么样」，本手册回答「今天打开 IDE 该干什么、哪些自己写、哪些交给 Agent」。
>
> 适用仓库：`ysd-take-out`（master），基线 Spring Boot **3.5.16** / JDK **21** / Jakarta EE。

---

## 零点 · 一句话总纲

> **拆服务分五个阶段，每个阶段都是同一套动作：划边界 → 建模块 → 搬代码 → 加路由 → 删旧码。**
> **搬代码交给 Agent；划边界、写核心链路、排错、做决策，必须自己来。**

读这份手册的正确姿势：**每做完一个动作就回来打勾**，不要一次性通读后直接开干。

## 一、全局五阶段地图

```
┌────────────────────────────────────────────────────────────────┐
│ 阶段 0  基础设施 + 版本对齐    单体先注册进 Nacos，验证环境      │ ← 你现在在这里
│ 阶段 1  抽网关                所有请求先过网关，再转发到 ysd-server│
│ 阶段 2  剥离低耦合服务        先拆 user / admin / report          │
│ 阶段 3  剥离 Catalog          分类 + 药品 + 药品组合（三者不拆开）    │
│ 阶段 4  剥离订单服务（最难）  订单 + 购物车 + WebSocket + 定时任务│
│ 阶段 5  收尾                  Sentinel、链路追踪、文档聚合、容器化│
└────────────────────────────────────────────────────────────────┘
```

每个阶段的本质是**同一件事**：

```
把 ysd-server 里的一块代码搬到新服务
  ↓
在网关加一条路由，把对应路径转发到新服务
  ↓
ysd-server 里删掉这块代码
  ↓
验收：接口正常、Nacos 有注册、旧代码不残留
```

采用**绞杀者模式（Strangler Fig）**：新旧并存，按模块逐个剥离，每阶段都可独立上线、可秒级回滚（改一条网关路由即可切回 `ysd-server`）。

## 二、每个阶段内部的固定 5 个动作

不管拆哪个服务，套路完全一样：

| 动作 | 说明 | 谁做 |
|---|---|---|
| **1. 划边界** | 决定要拆哪些 Controller / Service / Mapper / XML | 人（核心决策） |
| **2. 建模块** | 新建 Maven 子模块，配 pom、启动类、application.yml | Agent 给骨架 |
| **3. 搬代码** | 复制相关类到新模块，改包名和 import | Agent（纯体力） |
| **4. 加路由** | 网关里加一条 Path → 新服务的路由 | 人（先跑通一条） |
| **5. 删旧代码** | ysd-server 里删掉已迁移代码，验证编译通过 | 人（确认绞杀成功） |

> **动作 1 和 5 是核心决策，动作 3 是纯体力活。** 判断「动作 1 划得对不对」的标准：能不能一次搬走、搬完不再需要跟 `ysd-server` 互相调用。

## 三、人 / Agent 分工总表

### 3.1 你必须自己做的（学习价值最高）

| 类别 | 具体内容 | 为什么必须自己做 |
|---|---|---|
| **架构决策** | 服务怎么拆、拆几个、哪些不拆 | 微服务的核心能力，外包就学不会 |
| **鉴权链路** | 网关 `AuthGlobalFilter` + 下游拦截器还原 `BaseContext` + Feign 透传 | 三处缺一不可，越权/取不到 userId 的根因 |
| **Feign 契约设计** | `ysd-api` 里定义哪些接口、出入参 | 接口设计是架构能力 |
| **分布式事务判断** | 哪些写要强一致、哪些可最终一致、要不要上 Seata | 最容易做错的决策 |
| **排错** | 启动失败、Nacos 注册不上、503、404 | 读堆栈和日志是微服务基本功 |
| **写笔记 / 复盘** | 每阶段结束用自己的话总结 | 检验是否真的理解 |

### 3.2 Agent 帮你做的（纯体力 + 检索）

| 类别 | 具体内容 |
|---|---|
| **模块骨架生成** | 新服务的 pom、启动类、`application.yml` 模板 |
| **代码搬运** | 把 Controller/Service/Mapper/XML 复制到新模块，改包名、修 import |
| **格式化** | yaml 缩进、常量列表、SQL 格式化 |
| **模板生成** | ShedLock 配置、Redis Pub/Sub 订阅代码、Feign `fallbackFactory` 骨架 |
| **检索答疑** | 「`GlobalFilter` 怎么写」「`lb://` 底层做了什么」「Nacos 配置怎么加密」 |
| **代码 review** | 你写完关键代码后，让它指出线程安全问题、漏传 header、循环调用风险 |
| **重复性修改** | 批量改包名、批量加注解 |

### 3.3 绝对不要让 Agent 替你做的

| 反例 | 后果 |
|---|---|
| 「帮我把 `ysd-server` 拆成微服务」 | 它一口气全做完，你什么都没学到 |
| 「帮我设计 Feign 接口」 | 你失去了接口设计的练习 |
| 「帮我决定用不用 Seata」 | 你失去了分布式事务的判断训练 |
| 「启动报错怎么办」直接要答案 | 你失去了读日志、查文档的能力训练 |

### 阶段 2 · 剥离低耦合服务（先易后难）

按依赖度从低到高剥离：`ysd-user-service`（user / address_book）→ `ysd-admin-service`（employee / shop / file）→ `ysd-report-service`（report / workspace）。

| 动作 | 人 | Agent | 本仓库对应位置 |
|---|---|---|---|
| 选哪个先拆 | ✅ 自己判断依赖度 | — | 见上 |
| 复制代码 | — | ✅ 纯体力活 | `controller/user/UserController`、`AddressBookController`… |
| 改数据源 | ✅ 理解连接池 | — | 各服务独立 `application.yml` |
| **写 `BaseContext` 还原拦截器** | ✅ **核心** | review | 跨进程后 `ysd-common/BaseContext` 的 ThreadLocal 会失效，需在**每个下游服务**用拦截器把网关透传的身份写回 |
| 删 `ysd-server` 对应代码 | ✅ 确认绞杀成功 | — | 删 `controller/user/*`、`service/impl/*`、对应 `mapper` + `mapper/*.xml` |

**学习要点**：ThreadLocal 为什么跨进程失效、拦截器如何还原上下文（**三处缺一不可：网关透传 → Feign/header 携带 → 下游还原**）。

**验收**：被剥离的接口经网关正常；`ysd-server` 中对应代码已删除且无编译错误。

## 六、回退策略（每个阶段通用）

- 每阶段开始前给 `ysd-server` 全量可运行版本**打 tag**。
- 网关路由配置支持**按路径切回 `ysd-server`**。
- 任何阶段出问题，**改一条路由即可回退，无需回滚数据**。

---

## 七、红线提醒（避免过度设计）

1. 不要把 11 张表拆成 11 个服务——Database-per-service ≠ Table-per-service。
2. 不要拆分类 / 药品 / 药品组合（同一限界上下文）。
3. 不要拆购物车（与订单写入路径深度耦合）。
4. 不要所有事务都上 Seata（能本地事务的绝不跨服务，能最终一致的绝不强一致）。
5. 不要用 MQ 做同步查询（Feign 够用就别上 MQ）。
6. 不要一开始就上 K8s + 服务网格。
7. 不要为了微服务而保留 `ysd-pojo` 共享模块（共享领域模型反模式的入口）。
8. 不要跳过观测性改造（没有链路追踪的微服务排障成本极高）。
