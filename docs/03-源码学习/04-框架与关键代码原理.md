## 一、Spring Boot 启动与自动配置

### 1.1 真实启动类
| 服务 | 类 | 关键注解 |
|---|---|---|
| order | `ysd-order-service/.../YsdOrderServiceApplication.java:20-25` | `@SpringBootApplication @EnableTransactionManagement @EnableScheduling @EnableSchedulerLock @EnableDiscoveryClient @EnableFeignClients(basePackages="com.ysd.api.client")` |
| gateway | `ysd-gateway/.../ysdgateway/YsdGatewayApplication.java:7` | `@SpringBootApplication(scanBasePackages={"com.ysd.ysdgateway","com.ysd.filter","com.ysd.properties"})` |
| 其余 | 各 `Ysd*Application.java` | 仅 `@SpringBootApplication` |

**【框架能力】** `@SpringBootApplication` = `@SpringBootConfiguration + @EnableAutoConfiguration + @ComponentScan`。`@EnableAutoConfiguration` 通过 `spring-boot-autoconfigure` 的 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 加载；引入 `mybatis-spring-boot-starter`/`druid-spring-boot-3-starter`/`pagehelper-spring-boot-starter` 后对应自动配置自动生效（本项目**没有**手写 `SqlSessionFactory` 之类）。

**【项目自写】** order 服务额外挂的四个开关：
- `@EnableTransactionManagement`：开启注解式事务（与 `@Transactional` 配套）。
- `@EnableScheduling`：开启 `@Scheduled` 定时任务。
- `@EnableSchedulerLock(defaultLockAtMostFor="PT10M")`：ShedLock 总开关（`ShedLockConfiguration.java:18-22` 提供 `RedisLockProvider`）。
- `@EnableFeignClients(basePackages="com.ysd.api.client")`：扫描 `ysd-api` 里的 `@FeignClient` 生成代理。

**【项目自写】** 网关的 `scanBasePackages` 显式包含 `com.ysd.filter`、`com.ysd.properties`——因为 `AuthGlobalFilter` 和 `JwtProperties` 不在启动类同包/子包下，**默认扫描不到**，必须手动指定。这是「改了包结构导致 Bean 找不到」的典型排查点。

### 1.2 配置加载顺序（本项目）
`application.yml`（各服务）→ 环境变量占位（如 `${ALIYUN_OSS_ACCESS_KEY_ID:}`，admin `application.yml:48`）。**未见** `application-dev.yml`/profile 激活（历史文件已随 ysd-server 删除）。

## 二、Spring IOC 与依赖注入

- **注入方式**：绝大多数用**字段注入** `@Autowired`（如 `OrderServiceImpl:52-63`）；少数用构造器注入（`CatalogCacheHelper:75`、`WsPushProducer:21`、`WsPushListener:20`）。
- **组件扫描**：各服务 `@SpringBootApplication` 扫 `com.ysd` 包（服务自己的 controller/service/mapper/config 在同包下）。
- **Mapper 注册**：接口用 `@Mapper`（`OrderMapper.java:13` 等）被 MyBatis 扫描成代理 Bean。**【框架能力】**
- **公共 Bean】**：`RedisTemplate`（catalog/admin 的 `RedisConfiguration:23-61`）、`ServerEndpointExporter`（push `WebSocketConfiguration:14-16`）、`OpenAPI/GroupedOpenApi`（各服务 WebMvcConfiguration）。
- **特意不加 `@Component` 的类】**：`InnerIdentityInterceptor`（`InnerIdentityInterceptor.java:16` 注释）——由各服务在 `WebMvcConfiguration` 里 `new` 出来手动注册，避免被组件扫描全局生效。

**【静态推断】** 字段注入的缺点：难做单元测试、掩盖循环依赖。order 服务存在已知循环依赖，用 `spring.main.allow-circular-references: true`（`order/application.yml:11-12`）放开——注释说明是 `WebSocketServer(@Component)` 与 Redis 监听容器互相引用（迁移前遗留）。

## 三、AOP：公共字段自动填充（本项目最典型的 AOP）

### 3.1 三件套
| 元素 | 位置 |
|---|---|
| 注解 | `common/annotation/AutoFill.java`（`OperationType value()`） |
| 枚举 | `common/enumeration/OperationType.java`（INSERT/UPDATE） |
| 切面 | `common/aspect/AutoFillAspect.java` |
| 常量 | `common/constant/AutoFillConstant.java`（setCreateTime 等 4 个方法名） |

### 3.2 切点与通知（源码确认）
```java
// AutoFillAspect.java:31
@Pointcut("execution(* com.ysd.mapper.*.*(..)) && @annotation(com.ysd.annotation.AutoFill)")
// :37
@Before("autoFillPointCut()")
public void autoFill(JoinPoint joinPoint) { ... :38-84 }
```
- 匹配条件：**任意 `com.ysd.mapper` 包下的方法** 且 **方法上有 `@AutoFill`**。
- INSERT：反射调用 `setCreateTime/setCreateUser/setUpdateTime/setUpdateUser`（`:60-68`）。
- UPDATE：只填 `setUpdateTime/setUpdateUser`（`:75-78`）。
- 值来源：`LocalDateTime.now()` + `BaseContext.getCurrentId()`（`:53-54`）。

### 3.3 实际挂载点（`grep @AutoFill` 确认）
`EmployeeMapper`（insert/update）、`CategoryMapper`、`DrugMapper`、`DrugComboMapper`（admin/catalog/report 各自的副本）。
**`OrderMapper` 没有 `@AutoFill`** → 下单不会自动填充（orders 表也确无 create_time 列）。

### 3.4 为什么这样设计 / 局限
- **目的**：把「谁在何时创建/修改」这类横切逻辑从每个 Service 抽离，Service 里因此**注释掉了**手写的 `setCreateTime`（如 `EmployeeServiceImpl:87-93`、`CategoryServiceImpl:55-58`）。
- **【框架能力】** `@Aspect/@Pointcut/@Before` 是 Spring AOP；底层对「实现接口的 Bean」默认 JDK 动态代理，无接口用 CGLIB。Mapper 是接口 → JDK 代理，`@Before` 在调用代理方法前触发。
- **局限**：切点写死 `com.ysd.mapper` 包，若有 Mapper 移包会静默失效；靠**方法名常量**反射，实体改名/改签会抛 `RuntimeException`（`AutoFillAspect:69-70`）。

## 四、Spring MVC 请求处理过程（本项目）

### 4.1 处理链（源码确认）
```
HTTP → Tomcat → DispatcherServlet
 → HandlerMapping 找到 Controller 方法
 → HandlerInterceptor.preHandle（本项目注册的 3 类拦截器）
 → HandlerAdapter + 参数解析（@RequestBody/@PathVariable）
 → Controller 方法
 → HttpMessageConverter 序列化返回（被替换成 JacksonObjectMapper）
 → postHandle / afterCompletion
```

### 4.2 拦截器注册（本项目）
| 服务 | 文件 | 拦截路径 |
|---|---|---|
| user | `config/WebMvcConfiguration.java:34-39` | `/user/user/**,/user/addressBook/**`（排除 login）+ `/inner/**` |
| admin | `config/WebMvcConfiguration.java:31-33` | `/admin/employee/**,/admin/shop/**,/admin/common/**`（排除 login） |
| catalog | `config/WebMvcConfiguration.java:42-49` | admin 三前缀 + user 三前缀 + `/inner/**` |
| order | `config/WebMvcConfiguration.java:41-45` | `/admin/order/**` + `/user/order/**,/user/shoppingCart/**` |

`HandlerInterceptor`（Servlet 层，`preHandle` 返回 boolean）与网关 `GlobalFilter`（WebFlux 响应式，`Mono<Void>`）是**两套机制**，别混。

### 4.3 消息转换器（源码确认）
各服务 `WebMvcConfiguration.extendMessageConverters()` 遍历转换器，把 `MappingJackson2HttpMessageConverter` 的 `ObjectMapper` 替换为自定义 `JacksonObjectMapper`（如 `catalog/.../WebMvcConfiguration.java:86-94`）。
`JacksonObjectMapper`（`common/json/JacksonObjectMapper.java:32-50`）：
- 关闭 `FAIL_ON_UNKNOWN_PROPERTIES`（前端多传字段不报错）。
- `LocalDateTime` 用 `yyyy-MM-dd HH:mm` 序列化（`:29`，注意是**到分钟**）。

## 六、MyBatis 工作流（本项目重点）

### 6.1 配置（各服务 `application.yml`）
```yaml
mybatis:
  mapper-locations: classpath:mapper/*.xml
  type-aliases-package: com.ysd.entity
  configuration:
    map-underscore-to-camel-case: true
```

### 6.2 注解 + XML 混合（**重要**）
本项目 Mapper **两套写法并存**：
| Mapper | XML 中的语句 | 注解语句 |
|---|---|---|
| `OrderMapper` | `insert`、`update`、`pageQuery` | `getByNumber`(@Select)、`getById`(@Select)、`countStatus`(@Select)、`updateStatus`(@Update)、`getByStatusAndOrderTime`(@Select) |
| `ShoppingCartMapper` | `list`、`insertBatch` | `updateNumberById`(@Update)、`insert`(@Insert)、`deleteByUserId`(@Delete) |
| `OrderDetailMapper` | `insertBatch` | `getByOrderId`(@Select) |

**排查 SQL 时两处都要看**：方法在接口上有 `@Select/@Update/@Insert/@Delete` 就是注解 SQL，否则去 XML 找。

### 6.3 关键机制
- **主键回填**：`<insert useGeneratedKeys="true" keyProperty="id">`（`OrderMapper.xml:6`）→ 插入后 `orders.getId()` 可用（下单靠它关联明细）。
- **下划线↔驼峰**：`map-underscore-to-camel-case: true` 让 `order_time` → `orderTime`。
- **动态 SQL**：`<where>/<if>/<set>/<foreach>`（`OrderMapper.xml`、`ShoppingCartMapper.xml:29`）。
- **关联查询**：`DrugMapper.xml:22-37` `drug d left outer join category c`（同库同服务内 JOIN，合法）。
- **分页**：PageHelper（见 §七）。

## 七、分页与 PageHelper（框架能力）

```java
// OrderServiceImpl.pageQuery4User():210
PageHelper.startPage(pageNum, pageSize);
Page<Orders> page = orderMapper.pageQuery(dto);  // 紧跟的第一条 select 被拦截加 limit
```
PageHelper 通过 MyBatis `Interceptor` 织入：`startPage` 把分页参数放 ThreadLocal，拦截下一条 SQL 自动加 `limit` 并查总数。**陷阱**：`startPage` 之后必须紧跟**唯一一条**查询，中间插别的查询会错位。

## 八、事务边界与回滚条件

### 8.1 本项目 `@Transactional` 分布（`grep` 确认）
| 位置 | 注解 |
|---|---|
| `OrderServiceImpl.submitOrder():69` | `@Transactional(rollbackFor = Exception.class)` |
| `DrugServiceImpl.save/delete/updateWithSpec` | `@Transactional`（update 带 rollbackFor） |
| `DrugComboServiceImpl` 三处 | `@Transactional` |
| `AddressBookServiceImpl` 一处 | `@Transactional` |
| `OrderServiceImpl.payment()/paySuccess()` | **无事务** |

### 8.2 要点
- **`rollbackFor=Exception.class` 的意义**：Spring 默认只对 `RuntimeException`/`Error` 回滚，**受检异常不回滚**。下单显式声明，保证任何异常都回滚。
- **事务代理**：`@Transactional` 走 Spring AOP 代理，**同类内部方法互调不生效**（不会二次过代理）。本项目下单是「Controller → 代理的 submitOrder」，正常生效。
- **【静态推断】事务内含 Feign 调用**（`submitOrder:74`）→ 长事务风险（见 03 链路二）。
- **无事务的方法**：`payment()` 改订单状态是单条 update，无事务可接受；但若将来「改状态 + 补记录」多步操作需补事务。

## 十一、线程池、异步、定时任务、消息队列

| 能力 | 来源 | 本项目用法 |
|---|---|---|
| 定时任务 | **框架** `@Scheduled` | `OrderTask.processTimeoutOrder():24`（每分钟）、`processDeliveryOrder():45`（每天 1 点） |
| 分布式定时锁 | **三方** ShedLock | `@SchedulerLock` + `ShedLockConfiguration.java`（Redis 存储，前缀 `ysd-order`） |
| 自建线程池 | **项目** | `CatalogCacheHelper:62-68` 一个 2 线程 daemon 调度器做延迟双删；`@PreDestroy` 关闭（`:70-73`） |
| MQ 生产 | **三方** Spring AMQP | `WsPushProducer:25` `rabbitTemplate.convertAndSend` |
| MQ 消费 | **三方** | `WsPushListener:24` `@RabbitListener(queues="#{wsPushQueue.name}")` |
| 异步 | 未使用 | 未见 `@Async`/`@EnableAsync` |

**【静态推断】** ShedLock 的 `lockAtMostFor`/`lockAtLeastFor`（`OrderTask:25,46`）保证多实例同一时刻只跑一个；但 ShedLock **只防重复执行，不保证任务本身幂等**，任务内 update 仍是逐条循环。
