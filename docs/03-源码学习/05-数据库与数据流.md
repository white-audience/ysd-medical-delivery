## 二、表结构、主键、唯一约束、索引

**索引现状（源码确认——来自建表语句）**：只有主键 + 4 个唯一索引，**没有任何普通索引、没有外键**。

| 表 | 主键 | 唯一索引 | 缺失的常用查询列索引 |
|---|---|---|---|
| `category` | id | `idx_category_name(name)` :72 | type(查询维度) |
| `drug` | id | `idx_drug_name(name)` :106 | **category_id**、status |
| `drug_spec` | id | 无 | **drug_id** |
| `drug_combo` | id | `idx_drug_combo_name(name)` :278 | **category_id** |
| `drug_combo_item` | id | 无 | **combo_id**、drug_id |
| `orders` | id | 无 | **user_id、status、number、order_time** |
| `order_detail` | id | 无 | **order_id** |
| `shopping_cart` | id | 无 | **user_id** |
| `user` | id | 无 | **openid**（登录唯一凭据却无唯一约束） |
| `address_book` | id | 无 | **user_id** |
| `employee` | id | `idx_username(username)` :167 | — |

**【静态推断】风险**：`orders`/`order_detail`/`shopping_cart` 的外键列无索引 → 依赖这些列的查询在数据量增长后会全表扫描。**仅凭「无索引」推断慢查询，不代表线上一定慢**（数据量小则无感）；需 `EXPLAIN` 实测。

## 三、Entity / DTO / VO 与字段映射

- 表↔实体：`orders`↔`Order(entity Orders.java)`、`drug`↔`Drug`、`drug_combo`↔`DrugCombo`、`shopping_cart`↔`ShoppingCart`、`user`↔`User`、`address_book`↔`AddressBook`、`employee`↔`Employee`、`order_detail`↔`OrderDetail`、`drug_spec`↔`DrugSpec`、`drug_combo_item`↔`DrugComboItem`、`category`↔`Category`。

- 状态常量内嵌实体：`Orders` 状态 `1..6`（`Orders.java:24-29`）、支付态 `0/1/2`（`:34-36`）。

## 四、重要 SQL 执行逻辑

| 场景 | SQL 位置 | 说明 |
|---|---|---|
| 下单插入 | `OrderMapper.xml:6-14` | 18 列 insert，`useGeneratedKeys` 回填 id |
| 订单明细批量插入 | `OrderDetailMapper.xml:7-13` | `<foreach>` 单条 SQL 多 values |
| 订单动态更新 | `OrderMapper.xml:16-29` | `<set>` 只更新非空字段（如只改 status） |
| 订单分页 | `OrderMapper.xml:31-54`（order/report 各一份） | `<where>` 动态条件 + `order by order_time desc`；**number/phone 用 `like '%x%'` 前置通配 → 无法走索引** |
| 订单号查订单 | `OrderMapper.java:25` @Select | 按 `number` 查，但 **number 无索引** |
| 状态计数 | `OrderMapper.java:51` @Select | `count(id) ... where status=?`，**status 无索引** |
| 超时订单 | `OrderMapper.java:67` @Select | `status=? and order_time < ?`，两列均无索引 |
| 销量 Top10 | `report/OrderMapper.xml:83-96` | `order_detail od, orders o` 隐式 JOIN + `GROUP BY od.name order by sum(number) limit 10`，**两表关联列无索引** |
| 药品分页 | `catalog/DrugMapper.xml:22-37` | `drug d left outer join category c`（同库同服务，合法） |
| 营业额统计 | `report/OrderMapper.xml:55-68`(sumByMap) | `sum(amount)` + 时间范围，`order_time` 无索引 |

## 五、分页、条件、关联、批量

- **分页**：PageHelper（见 04 §七）。`conditionSearch`/`pageQuery4User` 都先 `startPage` 再条件查询。
- **条件查询**：`<where><if>` 动态拼接；订单搜索的 `number/phone` 模糊查询为 **LIKE '%...%'**。
- **关联查询**：仅 catalog 的 drug↔category 同库 JOIN；**report 跨域直读**（orders/drug/drug_combo/user 表）。
- **批量**：`insertBatch` 用 `<foreach>` 拼多值（`OrderDetailMapper.xml`、`ShoppingCartMapper.xml:25-32`）。

## 六、事务的开始/提交/回滚

- 下单：`submitOrder` 事务覆盖 地址查询→插订单→插明细→清购物车；`rollbackFor=Exception.class` 全回滚（见 03 链路二）。
- 药品增删改、药品组合、地址簿：`@Transactional` 保证「主表 + 关联表」一致（如 `DrugServiceImpl.saveWithSpec:57` 同时写 drug + drug_spec）。
- **【静态推断】** 事务与缓存删除的时序：`DrugServiceImpl.updateWithSpec:148` 先删缓存再写库、提交后延迟再删——若事务回滚，第一次删只是「白删」，不会脏（注释 `:151-152` 说明）。

## 七、✅ 代码与数据库一致性（原不一致已消除）

**背景**：早前工作区有 4 个未提交文件（`ysd-pojo/entity/Drug.java`、`ysd-pojo/dto/DrugDTO.java`、`ysd-pojo/vo/DrugVO.java`、`ysd-catalog-service/.../mapper/DrugMapper.xml`），给 `drug` 表新增 5 列：
`prescriptionType`(处方药类型, 默认 0)、`manufacturer`(生产厂家)、`approvalNumber`(批准文号)、`indications`(适应症)、`contraindications`(禁忌)。
`DrugMapper.xml` 的 insert/update **已引用** `prescription_type, manufacturer, approval_number, indications, contraindications` 五列。

**现状（2026-10-21 已消除不一致）**：
1. 上述代码改动**已提交**（`git status` 干净）；
2. 这 5 列**已写入** `docker/mysql/init/01-schema.sql`（建表脚本）；
3. 并通过迁移 **001 / 002 / 003** 落到真实库（证据：`docs/05-测试与压测/evidence/schema-migrations-20261021.txt`）。

**【环境自检】**：新环境导入建表脚本后，执行 `SHOW COLUMNS FROM drug;` 确认这五列存在。若缺失，说明未执行初始化脚本/迁移，此时 catalog 的新增/修改药品会因 "Unknown column" 报错（读取因 `select *` 不受影响）。

## 八、潜在风险（区分「实际存在」与「潜在」）

| 风险 | 类型 | 依据 |
|---|---|---|
| N+1 查询：订单分页逐条查明细 | 【源码确认】 | `OrderServiceImpl.pageQuery4User():222-234` 循环内 `orderDetailMapper.getByOrderId()`；`getOrderVOList():349-361` 同样逐条 |
| `orders` 外键列无索引导致统计/筛选全表扫 | 【静态推断】 | 建表语句无索引；需 EXPLAIN |
| `order_detail.order_id` 无索引加剧 N+1 成本 | 【静态推断】 | 同上 |
| `user.openid` 无唯一约束 + 无索引 | 【静态推断】 | 登录按 openid 查全表；并发首登可能重复注册 |
| 订单号 `System.currentTimeMillis()` 可能重复且 `number` 无唯一索引 | 【静态推断】 | `OrderServiceImpl:98` |
| 模糊查询 `LIKE '%x%'` 无法走索引 | 【静态推断】 | `OrderMapper.xml:34-39` |
| 无外键 → 无数据库级引用完整性 | 【源码确认】 | 建表语句 |
| 字符集混用 utf8mb3/utf8mb4 | 【源码确认】 | 各列 CHARSET 不一 |
| 并发购物车重复行 | 【静态推断】 | `addShoppingCart` 无事务无锁（见 03 链路三） |
| 表列注释与用途不符（`shopping_cart.user_id` 注释"主键"） | 【源码确认】 | 建表语句 :331 |
