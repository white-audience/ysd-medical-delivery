# 08 · 项目源码学习路线

> 面向：有 Java 基础、对本项目部分实现不熟、以求职为目标的开发者。
> 原则：**不要求一次看懂全部**；每个任务都可独立完成，有明确的「验证动作」和「完成标准」。
> 三个阶段的划分：①建立全局认知 → ②吃透核心链路 → ③深入框架/数据/排查。
> 每项任务给出：**要读的文件 / 要能回答的问题 / 必须掌握的知识点 / 验证任务 / 完成标准 / 面试价值**。
> 优先级从高到低；先做「最容易在面试被追问、又最能体现后端能力」的。

---

## 阶段一 · 建立全局认知（预计 1–2 天）

> 目标：能画出架构图、能从一个 URL 找到后端实现。

### 任务 1.1　跑起来并认识模块（P0）
- **读**：`README.md`、根 `pom.xml:15-26`、`docs/01-项目概览/01-项目全景图.md`。
- **要回答**：有几个模块？哪些能启动？各占什么端口？`ysd-api` 是服务吗？
- **知识点**：Maven 多模块、父子工程、`<dependencyManagement>` BOM。
- **验证**：按 `docs/04-运维与故障排查/环境变量配置说明.md` 起 MySQL/Redis/Nacos，`mvn clean install -DskipTests`，再启动 order + gateway，访问 Nacos 看到注册。
- **完成标准**：Nacos 服务列表出现你启动的服务名。
- **面试价值**：能讲清工程结构与启动顺序。

### 任务 1.2　跟着一条请求走通（P0）
- **读**：`ysd-gateway/.../application.yaml:34-70`、`filter/AuthGlobalFilter.java`。
- **要回答**：请求 `/user/shoppingCart/list` 命中哪条路由？被路由到哪个服务？鉴权在哪做？
- **知识点**：Spring Cloud Gateway 路由谓词、`lb://` 与 Nacos 的关系、GlobalFilter。
- **验证**：浏览器/curl `http://localhost:9000/user/shop/status`（白名单，无 token 应能通）。
- **完成标准**：能不看文档说出 6 条路由的目标服务。
- **面试价值**：网关统一鉴权是高频考点。

### 任务 1.3　接口 → 类的映射能力（P1）
- **读**：`docs/03-源码学习/02-源码导航地图.md` 的接口清单。
- **验证**：随机抽 5 个接口，找出对应 Controller 方法所在行。
- **完成标准**：任意给一个 URL，30 秒内定位到类和方法。

## 阶段二 · 理解核心业务链路（预计 3–5 天）

> 目标：能独立讲解登录、下单、缓存三条链路。

### 任务 2.1　登录与鉴权（P0）
- **读**：`user/controller/user/UserController.java:42`、`service/impl/UserServiceImpl.java:38-84`、`common/utils/JwtUtil.java`、`AuthGlobalFilter.java`、各 `JwtToken*Interceptor.java`。
- **要回答**：登录和鉴权的区别？token 怎么生成、怎么校验？`X-Identity-Id` 谁写谁读？为什么先删它？
- **知识点**：JWT 结构、jjwt 0.12 的密钥校验、拦截器 vs 网关过滤器、ThreadLocal 上下文。
- **验证**：调登录接口拿 token；用错的头名（如 `Authorization`）请求，观察 401。
- **完成标准**：能画出「登录」与「后续请求鉴权」两张不同的时序图。
- **面试价值**：鉴权是初级岗必问。

### 任务 2.2　下单事务链路（P0，最高优先）
- **读**：`order/controller/user/OrderController.java:29`、`service/impl/OrderServiceImpl.java:69-128`、`mapper/OrderMapper.java`、`OrderMapper.xml`、`OrderDetailMapper.xml`、`ysd-api/client/UserClient.java`、`user/controller/inner/InnerAddressBookController.java`。
- **要回答**：事务覆盖哪些步骤？地址从哪来？订单号怎么生成？明细从哪来？哪一步跨服务？
- **知识点**：`@Transactional` 边界与 `rollbackFor`、Feign 调用、`useGeneratedKeys`、快照模式。
- **验证**：手动清空购物车后下单，看是否抛「购物车为空」；查 orders 是否无残留。
- **完成标准**：白板上默写下单 7 步 + 每步所在类。
- **面试价值**：最能体现事务/跨服务理解的链路。

### 任务 2.3　支付与来单提醒（P1）
- **读**：`OrderServiceImpl.payment():136`、`paySuccess():175`、`notify/PayNotifyController.java`、`mq/WsPushProducer.java`、`push/.../{RabbitConfig,WsPushListener,WebSocketServer}.java`。
- **要回答**：现在真的走微信支付吗？`payment` 和 `paySuccess` 有什么区别？消息怎么到 WebSocket？
- **知识点**：模拟支付现状、fanout 交换机、匿名队列、多实例广播。
- **验证**：起 RabbitMQ，观察 `ws.broadcast` 交换机和队列；调 `/notify/paySuccess` 观察 push 日志。
- **完成标准**：能解释「为什么模拟支付触发了、商家却没收到提醒」。
- **面试价值**：诚实讲「假支付」反而加分。

### 任务 2.4　缓存读写（P0）
- **读**：`catalog/service/impl/DrugServiceImpl.java:148-228`、`cache/CatalogCacheHelper.java`、`config/RedisConfiguration.java`。
- **要回答**：三件套分别在哪几行？延迟双删时机？本地锁为什么多实例失效？
- **知识点**：缓存击穿/穿透/雪崩、双检锁、TTL 抖动、SCAN、延迟双删。
- **验证**：改一个药品价，先看用户端（应刷新）；`redis-cli -n 10 --scan --pattern 'ysd:catalog:drug:*'` 看 key。
- **完成标准**：能说出每个 key 的命名和过期策略。
- **面试价值**：缓存是面试重灾区。

### 任务 2.5　加购物车跨服务（P1）
- **读**：`ShoppingCartServiceImpl.java:35-103`、`ysd-api/client/CatalogClient.java`、`fallback/CatalogClientFallbackFactory.java`、`interceptor/FeignRequestInterceptor.java`。
- **要回答**：什么时候触发 Feign？失败怎么降级？快照 DTO 为什么只三个字段？
- **验证**：关掉 catalog 服务，加购物车，看是否返回「商品服务繁忙」。
- **完成标准**：能解释 fail-fast 降级的理由。
- **面试价值**：服务容错考点。

## 阶段三 · 深入框架 / 数据 / 排查（预计 5–7 天）

> 目标：能解释原理、能定位问题、能提改进。

### 任务 3.1　AOP 与公共字段填充（P1）
- **读**：`common/aspect/AutoFillAspect.java`、`annotation/AutoFill.java`、任一 `@AutoFill` 的 Mapper。
- **要回答**：切点表达式匹配什么？为什么订单不填充？
- **验证**：新增一个员工，看日志 `开始进行公共字段填充`，查库 create_time/create_user。
- **完成标准**：能写一个新的 `@AutoFill` 方法并生效。

### 任务 3.2　MyBatis 注解+XML 与事务原理（P1）
- **读**：`OrderMapper.java` + `OrderMapper.xml`、各 `application.yml` 的 mybatis 段、`OrderServiceImpl:69`。
- **要回答**：同一个 Mapper 哪些在注解哪些在 XML？`startPage` 后为什么要紧跟查询？
- **验证**：开 `logging.level.com.ysd.mapper=DEBUG`，观察 SQL 与分页 limit。
- **完成标准**：能解释 PageHelper 的 ThreadLocal 机制与陷阱。

### 任务 3.3　数据库与数据流（P0）
- **读**：`docker/mysql/init/01-schema.sql`、`docker/mysql/migrations/*.sql`、`docs/03-源码学习/05-数据库与数据流.md`。
- **要回答**：哪些表无索引？N+1 在哪？有没有外键？
- **验证**：进 MySQL 执行 `EXPLAIN select * from orders where status=1;`，观察 `type`。
- **完成标准**：能列出一张「建议加的索引」清单并说明理由。
- ⚠️ **注意**：`drug` 的 5 个处方药字段已写入 `docker/mysql/init/01-schema.sql`，并通过迁移 001/002/003 落到真实库；用 `SHOW COLUMNS FROM drug;` 确认。

### 任务 3.4　故障排查演练（P1）
- **读**：`docs/04-运维与故障排查/06-故障排查手册.md`。
- **验证**：故意制造 3 个故障各修一次：① 停 Redis 看定时任务/缓存；② 关 catalog 看 Feign 降级；③ 带错 token 看 401。
- **完成标准**：能按「现象→首查→验证→定位」说出来。

### 任务 3.5　安全与整改（P2）
- **读**：`docs/04-运维与故障排查/环境变量配置说明.md`、order/user 的 `application.yml` 微信段、admin 的 OSS 段。
- **要回答**：哪些密钥明文？整改模板在哪（admin 的 `${...}` 占位）？
- **验证**：不写代码，仅定位行号并口述整改方案。
- **完成标准**：能说明「只改代码不改 Key ≠ 修好」的理由。

### 任务 3.6　微服务组件验证（P2，可选）
- **读**：各 `application.yml` 的 sentinel/rabbitmq/tracing 段。
- **验证**：起 Zipkin（9411）看 traceId 串服务；起 Sentinel dashboard 看规则；起两个 order 实例看 ShedLock。
- **完成标准**：能区分「配置存在」与「功能已验证」，并说明验证方法。

## 完成后你应该能
- 用自己的话讲架构与核心业务；
- 从任一前端请求找到并解释后端实现；
- 说清 Controller→Service→Mapper 的调用关系；
- 解释关键代码为什么这么写；
- 找到 DB 操作、事务、缓存逻辑；
- 按错误现象定位代码和日志；
- 说出真实风险并给出合理改进；
- 面试时基于源码回答，而非背概念。

## 学习时的三条纪律
1. **以代码为准**：任何文档/注释与代码冲突，信代码；本套文档的行号随代码变动会过期。
2. **区分三态**：源码确认 / 静态推断 / 需运行验证——不要把自己没跑过的当已验证。
3. **能改再说懂**：每个模块的「验证任务」尽量真做一遍（不影响业务的读操作/查询优先）。
