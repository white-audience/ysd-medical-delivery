# 06 · 故障排查实战手册

> 统一结构：**现象 → 可能原因 → 先看什么 → 如何验证 → 如何定位 → 修复思路 → 如何回归验证**。
> 命令贴合本项目环境（Windows + bash、Java 21、Maven 3.9、MySQL 8、Redis 6379 / Redis Stack 6379、Ollama 18434、Nacos 8848、RabbitMQ 5672、网关 9000、业务服务 8081–8086、AI 服务 8088）。
> 凡依赖具体环境（中间件是否装、端口是否被占）的步骤，均标注「需先确认」。
> 与源码绑定处标注 `文件:行`。

## 1. 项目启动失败

- **可能原因**：端口占用；中间件未起（Nacos/MySQL/Redis）；配置项缺失（密钥占位为空）；Bean 创建失败（见 §3）。
- **先看**：控制台第一段 `APPLICATION FAILED TO START` 后的 `Description`/`Action`。
- **验证**：
  - 端口：`netstat -ano | findstr :9000`。
  - Nacos：Nacos 3.x 控制台 `http://127.0.0.1:8080`（compose 映射为 `http://localhost:8849`）；2.4+ 无默认账号，首次启动需初始化管理员（`curl -X POST "http://127.0.0.1:8848/nacos/v3/auth/user/admin" -d "password=nacos"`，compose 会自动执行）。
  - MySQL：`mysql -uroot -proot -e "show databases;"`。
  - Redis：`redis-cli -n 10 ping`（应返回 PONG）。
- **定位**：日志关键词 `Port 8085 was already in use`、`Connection refused`、`Cannot determine embedded database`。
- **修复**：杀占用进程或换端口；启动缺失中间件。
- **回归**：服务日志出现 `Started Ysd*Application in x seconds`；Nacos 服务列表可见。

## 2. Maven 依赖 / 编译失败

- **可能原因**：内部模块版本没走 BOM；未先 `install` 父工程/依赖模块；JDK 版本不符（要求 **21**）。
- **先看**：`Could not find artifact com.ysd:ysd-xxx:jar`（说明内部模块未装）；`invalid target release`。
- **验证**：`java -version`（须 21）；`mvn -v`。
- **定位**：内部模块用 `${project.version}` 由根 `pom.xml:50-68` 统一管理，写错版本会去远程找。
- **修复**：根目录 `mvn clean install -DskipTests` 后再跑单模块。
- **回归**：`mvn clean compile` 全模块 SUCCESS。

## 3. Spring Bean 创建失败

- **可能原因**：`@Autowired` 找不到 Bean（包没扫到）；循环依赖；`@ConfigurationProperties` 前缀写错。
- **先看**：`UnsatisfiedDependencyException` / `BeanCurrentlyInCreationException` / `NoSuchBeanDefinitionException`。
- **验证**：确认类在启动类扫描路径内。**注意网关** `YsdGatewayApplication:7` 显式 `scanBasePackages` 才扫得到 `com.ysd.filter`/`com.ysd.properties`——这两个包不在启动类子包下。
- **定位**：order 服务的循环依赖已用 `allow-circular-references: true`（`order/application.yml:11-12`）放开；若报循环依赖，先看该开关。
- **修复**：补扫描包 / 调整依赖方向 / 确认开关。
- **回归**：服务启动无 `BeanCreationException`。

## 4. 接口 400 / 401 / 403 / 404 / 500

### 401 未登录/过期
- **先看**：网关日志 `请求缺少 token` / `JWT 校验失败: {}`（`AuthGlobalFilter:87,113`）。
- **验证**：请求头名对不对——**管理端 `token`、用户端 `authentication`**（`AuthGlobalFilter:79-83`）。
- **定位**：头名错 / token 过期（TTL 2h）/ 网关与服务端 `*-secret-key` 不一致（升级 jjwt 前的旧 token 也失效，`JwtUtil:23`）。
- **修复**：重新登录拿新 token。
- **回归**：带新 token 业务接口 200。

### 403 `/inner/**` 被外部访问
- **说明**：**预期行为**（`AuthGlobalFilter:63-65`），内网接口只给 Feign。
- **验证**：确认请求路径以 `/inner/` 开头。

### 404 路径不对
- **先看**：网关路由表（`gateway/application.yaml:34-70`）是否有匹配前缀。
- **定位**：路径没被任何 `Path=` 谓词覆盖（如 `/admin/xxx` 非白名单前缀）。
- **验证**：`curl -i http://localhost:9000/<path>` 看是否 404 还是 503。

### 500 服务内部异常（**重点**）
- **先看**：目标服务日志的异常栈。
- **定位**：
  - **只有 order 服务与 ai 服务有全局异常处理器**（`ysd-order-service/handler/GlobalExceptionHandler.java`、`ysd-ai-service/handler/GlobalExceptionHandler.java`，`grep @RestControllerAdvice` 仅命中这两处）。**其它服务**业务异常无处理器 → 直接 500，前端拿到 Spring 默认错误体。
  - 常见来源：`AutoFillAspect` 反射失败（`AutoFillAspect:69-70` 抛 RuntimeException）。
- **修复**：给其余服务补 `@RestControllerAdvice`（**记录，勿擅改**）。
- **回归**：构造业务异常，看返回体是否为 `Result{code=0}`。

### 400 参数问题
- **说明**：项目**未用 Bean Validation**（无 `@Valid`），400 多来自 `@RequestBody` 反序列化失败（字段类型不符）或 `@PathVariable` 类型不匹配。
- **先看**：日志 `HttpMessageNotReadableException` / `MethodArgumentTypeMismatchException`。

## 5. 前端请求失败 / 跨域

- **可能原因**：改端口后前端 `baseUrl` 未更新；nginx 反代配置；CORS。
- **先看**：浏览器 Network 面板的状态码与响应头。
- **验证**：
  - 小程序 `baseUrl` 应为网关 `http://localhost:9000`（README §6，⚠️前端源码不在本仓库，需自行核对 `common/vendor.js`）。
  - nginx：`/api/` 应反代到 `localhost:9000/admin/`（`<nginx-root>\conf\nginx.conf`）。
- **定位**：CORS 报错需看响应头 `Access-Control-Allow-*`。**未见**全局 CORS 配置——同源（走 nginx 或网关）可避免。
- **回归**：前端能拿到 `Result` JSON。

## 6. 数据库连接失败

- **可能原因**：MySQL 未起 / 库名错 / 账号密码错 / 时区。
- **先看**：`Communications link failure` / `Unknown database 'ysd_take_out'` / `Access denied`。
- **验证**：`mysql -uroot -proot -e "use ysd_take_out; select 1;"`。
- **定位**：统一在服务 `application.yml` 的 `spring.datasource.druid.url`（`ysd_take_out`）。
- **修复**：启动 MySQL、导入库、核对凭据。
- **回归**：服务启动后能查询列表接口。

## 7. SQL 执行异常 / 查询缓慢

### 7.1 `Unknown column 'xxx'`（**本项目特有的高危项**）
- **背景（源码确认，已消除）**：`Drug` 的 5 个字段（`prescription_type` 等）已提交，并写入建表脚本 `docker/mysql/init/01-schema.sql` 与 `DrugMapper.xml`；迁移 `001/002`（`docker/mysql/migrations/`）与 `003`（`docs/04-运维与故障排查/`）已落地。若旧环境未执行迁移，仍可能报此错。
- **先看**：catalog 服务日志的 SQL 报错。
- **验证**：`mysql -uroot -proot -e "SHOW COLUMNS FROM ysd_take_out.drug;"`，确认 `prescription_type/manufacturer/approval_number/indications/contraindications` 是否存在。
- **定位**：不存在 → 迁移未执行。
- **修复**：执行对应 `ALTER TABLE`（**属用户进行中的改造，勿擅改**）。
- **回归**：新增/修改药品接口成功。

### 7.2 查询慢
- **可能原因**：多列无索引（`orders.user_id/status/number/order_time`、`order_detail.order_id`，见 05 §二）。
- **先看**：慢查询日志（需先开 `slow_query_log`）。
- **验证**：`EXPLAIN <SQL>`，看 `type=ALL`、`rows` 大。
- **定位**：订单分页/统计（`OrderMapper.xml`）、`getSalesTop10`（`report/OrderMapper.xml:83-96`）。
- **修复**：加索引（如 `orders(status,order_time)`、`order_detail(order_id)`）——**需评估后再改**。
- **回归**：EXPLAIN 由 `ALL` 变 `range/ref`。
- **注意**：**未运行 EXPLAIN，不判定线上一定慢**（数据量小则无感）。

## 8. Redis 连接失败 / 缓存不更新

### 8.1 连接失败
- **验证**：`redis-cli -n 10 ping`。
- **定位**：各服务 `spring.data.redis`（host/port/**database: 10**）。
- **【静态推断】** catalog 读路径未对 Redis 异常兜底 → Redis 挂会连带接口 500。
- **修复**：恢复 Redis；建议加降级。

### 8.2 改药品后用户端仍看到旧数据
- **先看**：Redis 是否有残留 key。
- **验证**（生产用 SCAN）：`redis-cli -n 10 --scan --pattern 'ysd:catalog:drug:*'`。
- **定位**：延迟双删第二次删除未触发——检查 `scheduleDelayedEvict`（`CatalogCacheHelper:192-211`）是否在事务内被调用（依赖 `afterCommit`），日志关键词 `延迟删除缓存失败`（`:197`）。
- **修复**：确认 `@Transactional` 生效；检查调度器线程未耗尽。
- **回归**：改价后立刻刷用户端，应为新值。

### 8.3 反序列化失败
- **现象**：`InvalidDefinitionException` / `ClassCastException` / 拿到 `LinkedHashMap`。
- **定位**：value 用 `GenericJackson2JsonRedisSerializer` + 类型白名单（`RedisConfiguration:39-51`）。新增非 `com.ysd` 类型需加入白名单。
- **回归**：写读一致。

## 9. 事务未回滚 / 数据不一致

- **先看**：方法是否走了代理。**同类内部方法直接调用不会触发事务**。
- **验证**：在 `submitOrder` 内故意抛异常，观察 orders 是否有残留行。
- **定位**：`@Transactional(rollbackFor=Exception.class)`（`OrderServiceImpl:69`）覆盖下单；`payment()/paySuccess()` **无事务**。
- **修复**：确保注解方法被外部（代理）调用；多步写操作补事务。
- **回归**：异常后无脏数据。

## 10. 并发导致重复数据 / 覆盖

- **场景 A：下单号重复**。原因 `number=System.currentTimeMillis()`（`OrderServiceImpl:98`）+ `number` 无唯一索引。
  - 验证：并发 submit，统计重复 number。
  - 修复：雪花 ID + 唯一索引。
- **场景 B：购物车重复行/数量覆盖**。原因 `addShoppingCart` 无事务无锁。
  - 验证：同用户并发加同款。
  - 修复：唯一索引 + `insert ... on duplicate key update`。
- **场景 C：缓存击穿**（多实例）。原因本地锁跨 JVM 无效（`CatalogCacheHelper:88-90` TODO）。
  - 验证：多实例冷启动压测 DB QPS。
  - 修复：分布式锁/逻辑过期。

## 11. 消息积压 / 定时任务未执行

### 11.1 MQ 消息未消费（来单提醒不发）
- **先看**：RabbitMQ 管理台 `http://localhost:15672`（guest/guest）是否有 `ws.broadcast` 队列/消息。
- **验证**：
  - push 服务日志 `收到广播消息，推送给本实例客户端`（`WsPushListener:26`）。
  - **重要**：模拟支付路径（`payment()`）**根本不 push**——只有 `/notify/paySuccess` 才 `WsPushProducer.push`（见 03 链路二）。所以"支付后来单提醒不来"很可能是**预期**。
- **定位**：确认 `WsPushProducer` 是否被调用。
- **修复**：如需要，让模拟支付也走 `paySuccess` 逻辑（记录，勿擅改）。

### 11.2 定时任务未按预期执行
- **先看**：order 日志 `定时处理支付超时订单`（`OrderTask:27`，每分钟）。
- **验证**：查 `orders where status=1 and order_time < now-15min`。
- **定位**：`@SchedulerLock` 依赖 Redis（`ShedLockConfiguration`）——**Redis 不通则锁获取失败、任务不执行**。
- **修复**：恢复 Redis。
- **回归**：超时订单被置 `status=6`。

## 12. 服务运行一段时间变慢 / CPU、内存异常

- **先看**：`jps` 找到 PID → `jstack <pid>`（看阻塞线程）/ `jstat -gc <pid> 1000`（GC 频率）。
- **定位方向**：
  - **本地锁 map 不清理**（`CatalogCacheHelper:57-59` 注释，key 有界暂可接受）。
  - **延迟双删调度器线程**（2 个，`:62-68`）若任务堆积会占用。
  - N+1 查询（订单分页逐条查明细，`OrderServiceImpl:222-234`）在数据量大时拖慢。
- **验证**：开 MyBatis SQL 日志，数一次分页的 SQL 条数。
- **修复**：批量化查询、加索引、调线程池。
- **回归**：压测 RT 回落。

## 13. 日志不足，定位不了

- **现状（源码确认）**：日志按 `logging.pattern.level` 带 `traceId`（各 `application.yml`，如 `order/application.yml:89-91`）。
- **增强**：
  - 开 MyBatis SQL：`logging.level.com.ysd.mapper=DEBUG`（Feign 日志已设 `logging.level.com.ysd.api.client=DEBUG`，`order/application.yml:93`）。
  - 链路追踪：确保 Zipkin 在跑（9411），用 traceId 串服务。
- **回归**：能从 traceId 还原整条调用链。
