# 8080 端口冲突处理 · NI Application Web Server 停用与回滚记录

> ⚠️ **归档说明**：本文记录于微服务改造前期（2026-10）。文中提到的 `ysd-server` 单体已删除（现为网关 9000 + 各业务服务 8081–8086 + AI 8088），相关最新实现请参阅 `docs/02-架构设计与开发/` 或对应执行记录。

> 处理日期：**2026-10-07**
> 环境：Windows 11 / 项目 `ysd-take-out`（`ysd-server` 端口 = 8080，见 `ysd-server/src/main/resources/application.yml:2`）
> 处理动作：**停止**并将 `NIApplicationWebServer` 服务启动类型改为 **禁用（DISABLED）**，以释放 8080
> 本文用途：记录该变更的**回滚操作**，以便日后需要 NI Web 服务时恢复
> 相关文档：[[gateway-startup-fix]]（Nacos 端口 8858→8848 的修复）

---

## 一、背景与现象

启动 `ysd-server` 报 `Port 8080 was already in use`（Tomcat 无法绑定 8080）。

定位到占用方为进程 `ApplicationWebServer.exe`：

| 项 | 值 |
|---|---|
| 进程名 | `ApplicationWebServer.exe` |
| PID（处理时） | 10208 |
| 会话 | Session 0（Services） |
| 公司 / 签名 | National Instruments Corporation（签名有效） |
| 产品 | APPLICATIONWEBSERVER，版本 14.5.0f0 |
| 路径 | `<ni-webserver-exe>` |
| 所属服务 | `NIApplicationWebServer`（显示名 "NI Application Web Server"） |
| 原启动类型 | **Auto（开机自启）** |
| 监听 | `0.0.0.0:8080` |

**结论**：占用 8080 的是 **NI（National Instruments）软件自带的 Web 服务守护进程**，随 LabVIEW / NI-MAX / NI 驱动安装，属正版组件（签名有效），并非异常程序。它与 `ysd-server` 争抢 8080，导致后者无法启动。

---

## 二、已执行的变更（正向操作）

> ⚠️ 以下命令**需要管理员权限**（非提权 shell 会返回 `拒绝访问 / 错误 5`）。

```bat
:: 1) 停止服务
net stop NIApplicationWebServer

:: 2) 将启动类型设为禁用，开机不再自启
sc config NIApplicationWebServer start= disabled
```

执行结果（2026-10-07）：

```
stop    : NI Application Web Server 服务已成功停止。
disable : [SC] ChangeServiceConfig 成功
```

变更后状态：

| 检查项 | 结果 |
|---|---|
| `0.0.0.0:8080` 监听 | 无（端口已释放） |
| `ApplicationWebServer.exe` 进程 | 已退出 |
| 服务 `START_TYPE` | `4  DISABLED` |
| 服务 `STATE` | `1  STOPPED` |

---

## 三、回滚操作（恢复到处理前状态）

当需要重新启用 NI Web 服务时执行。**同样需要管理员权限。**

```bat
:: 1) 恢复启动类型为自动
sc config NIApplicationWebServer start= auto

:: 2) 立即启动服务
net start NIApplicationWebServer
```

预期结果：`[SC] ChangeServiceConfig 成功` + `NI Application Web Server 服务已经启动成功`。

### 回滚后可选的降级做法

若**只想临时占用 8080、不想开机自启**，可只启动、不改为 auto：

```bat
net start NIApplicationWebServer          :: 临时启动（本次开机有效）
:: 下次不再自动启动，因 start 类型仍为 disabled
```

> 注意：NI 服务一旦启动即会重新占用 `0.0.0.0:8080`，届时 `ysd-server` 将再次无法绑定该端口。二者**不能同时使用 8080**，需二选一：
> - 用 NI 服务 → 让 `ysd-server` 换端口（改 `application.yml:2` 的 `server.port`，如 8081）；
> - 用 `ysd-server` → 保持 NI 服务为 stopped/disabled（即当前状态）。

## 四、验证命令（正向 / 回滚通用）

```bat
:: 查看 8080 占用（无输出 = 端口空闲）
netstat -ano | findstr ":8080" | findstr LISTENING

:: 查看 NI 进程是否在跑
tasklist /FI "IMAGENAME eq ApplicationWebServer.exe"

:: 查看服务启动类型（2=AUTO 自动 / 3=MANUAL 手动 / 4=DISABLED 禁用）
sc qc NIApplicationWebServer | findstr START_TYPE

:: 查看服务当前状态（1=STOPPED 已停止 / 4=RUNNING 运行中）
sc query NIApplicationWebServer | findstr STATE
```

状态对照：

| 场景 | START_TYPE | STATE | 8080 占用 |
|---|---|---|---|
| 当前（已停用） | `4 DISABLED` | `1 STOPPED` | 空闲 |
| 回滚后（恢复） | `2 AUTO` | `4 RUNNING` | 被 NI 占用 |

---

## 五、影响范围说明

- **停用后受影响的功能**：NI 软件的 Web 服务能力，例如 LabVIEW Web Service、NI-MAX 远程配置页等基于该守护进程的功能将不可用。
- **不受影响**：NI 软件本体（LabVIEW、MAX、驱动）的本地功能正常运行。
- **可逆性**：完全可逆，按第三节回滚即可恢复。
