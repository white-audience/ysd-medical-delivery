# 数据库改名操作：`sky_take_out` → `ysd_take_out`

> ⚠️ **归档说明**：本文记录于微服务改造前期（2026-10）。部分方案已被后续架构取代，相关最新实现请参阅 `docs/02-架构设计与开发/` 或对应执行记录。

> 背景：项目品牌统一为**药速达智慧配送平台**（简称**药速达**），数据库名同步从 `sky_take_out`
> 改为 `ysd_take_out`，与应用配置保持一致。
> 适用：MySQL 8.x（Windows / Docker 均可）。**动手前请先备份。**

---

## 一、影响面

| 位置 | 说明 | 本次是否已改 |
|---|---|---|
| `ysd-server/src/main/resources/application-dev.yml` | `ysd.datasource.database` | ✅ 已改为 `ysd_take_out` |
| `README.md` / `md/*.md` | 文档中的库名引用 | ✅ 已改 |
| **MySQL 实例本身** | 实际存在的库 `sky_take_out` | ⬜ **需你按本文手动执行** |
| `ysd-server/src/test/resources/sql/*-h2.sql` | 单测用 H2 内存库，与库名无关 | 无需改 |

> ⚠️ 只要应用配置已指向 `ysd_take_out`，**而 MySQL 里还没有这个库，启动就会报
> `Unknown database 'ysd_take_out'`**。所以要么执行下面改名，要么把配置改回 `sky_take_out`。

---

## 二、前置：备份 + 停服

```bash
# 1) 先停掉 ysd-server / ysd-gateway，避免改库期间连接报错
# 2) 全量备份旧库（务必确认备份文件非空）
mysqldump -uroot -p --single-transaction --routines --triggers sky_take_out > sky_take_out_backup.sql

# 检查备份大小应 > 0 且包含 11 张表的 CREATE TABLE
ls -l sky_take_out_backup.sql
```

---

## 三、方案一（推荐）：导出 → 新建 → 导入

MySQL **不支持 `RENAME DATABASE`**，标准做法是重建库再导入。

```sql
-- 1) 新建目标库（字符集与原库一致：utf8mb4）
CREATE DATABASE IF NOT EXISTS ysd_take_out
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_general_ci;
```

```bash
# 2) 把备份导入到新库
mysql -uroot -p ysd_take_out < sky_take_out_backup.sql
```

> 💡 注意：上面备份命令**没有**用 `--databases`，所以导出的 SQL 里不含
> `CREATE DATABASE` / `USE` 语句，可安全导入到 `ysd_take_out`。
> 若你的备份用了 `mysqldump --databases sky_take_out ...`，SQL 里会带 `USE sky_take_out`，
> 导入时请先剥离：
> ```bash
> sed '/^USE `sky_take_out`;/d; /^CREATE DATABASE/d' sky_take_out_backup.sql > ysd_take_out.sql
> mysql -uroot -p ysd_take_out < ysd_take_out.sql
> ```

---

## 四、方案二：MariaDB 专用（如你用的是 MariaDB）

MariaDB 10.5.2+ 支持原子改名，最快：

```sql
RENAME DATABASE sky_take_out TO ysd_take_out;
```

MySQL 8 用户请用方案一。

---

## 五、确认配置

`ysd-server/src/main/resources/application-dev.yml` 应指向新库：

```yaml
ysd:
  datasource:
    host: localhost
    port: 3306
    database: ysd_take_out      # ← 必须是这个
    username: root
    password: ******
```

## 六、验证

```sql
-- 1) 新库存在且表数量为 11
SELECT COUNT(*) AS tables_in_new_db
FROM information_schema.tables
WHERE table_schema = 'ysd_take_out';
-- 期望：11

-- 2) 抽查数据是否随备份过来
SELECT COUNT(*) FROM ysd_take_out.employee;
SELECT COUNT(*) FROM ysd_take_out.orders;
```

```bash
# 3) 启动 ysd-server，确认无 Unknown database 报错
mvn -pl ysd-server spring-boot:run
# 4) 管理端登录 / 小程序浏览药品，验证读写正常
```

## 七、清理旧库（确认无误后再执行）

```sql
-- 建议观察 1~2 天，确认功能与数据都正常后再删
DROP DATABASE sky_take_out;
```

> 删除前请再确认 `sky_take_out_backup.sql` 已妥善保存。

---

## 八、回滚

只要还没 `DROP DATABASE sky_take_out`，回滚就是一步：把
`application-dev.yml` 的 `database` 改回 `sky_take_out`，重启即可。

---

## 九、常见坑

| 现象 | 原因 / 处理 |
|---|---|
| `Unknown database 'ysd_take_out'` | 只改了配置没建库 → 执行第三章 |
| 导入后表名/库名又变成旧的 | 备份用了 `--databases`，见方案一提示剔除 `USE`/`CREATE DATABASE` |
| 中文乱码 | 建库未指定 `utf8mb4`，或导入时客户端字符集不对（加 `--default-character-set=utf8mb4`）|
| 定时任务/WebSocket 报错 | 与库名无关，属多实例部署问题，见 `spring-cloud-migration-plan.md` |
