# 环境变量配置说明（ENV-SETUP）

> 本文档记录项目运行所需的外部环境变量，以及各环境下的设置方式。
> 首次拉取代码或更换机器时，请先按本文档配好环境变量再启动。

---

## ⚠️ 重要：旧密钥已泄露，必须轮换

**仅修改代码（把明文 Key 换成环境变量占位符）不等于修复安全问题。**

旧的 AccessKey 已经以明文形式提交进 Git 历史：

- `<ALIYUN_OSS_ACCESS_KEY_ID>`（AccessKey ID）
- `<ALIYUN_OSS_ACCESS_KEY_SECRET>`（AccessKey Secret）

只要这份历史还在，任何拿到仓库的人都能读到。**因此必须执行密钥轮换**：

1. 登录阿里云控制台 → **访问控制 RAM** → 用户 / AccessKey 管理。
2. 找到对应 AccessKey（ID 以 `LTAI` 开头的那把）→ **禁用**，随后**删除**。
3. 重新创建一对新的 AccessKey。
4. 将新 Key 通过下方的环境变量方式注入，**不要**再写回代码或配置文件。
5. （可选）为新的 RAM 用户收紧权限：只授予该 Bucket 的读写权限，避免使用主账号 Key。

> 只改代码不改 Key = 没修。旧 Key 只要没被禁用，攻击者仍可直接使用。

## 需要设置的环境变量清单

> 采集自仓库内所有 `application.yml` / `application.yaml` / `docker-compose.yml` 的 `${...}` 占位符（2026-10-21）。

### 1. 安全敏感（无默认值，必须显式设置）

| 变量名 | 说明 | 示例 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek 大模型 API Key。`ysd-ai-service` 中写作 `${DEEPSEEK_API_KEY}`**无默认值**，未设置时占位符无法解析，AI 服务启动会报错 | `sk-********` |
| `ALIYUN_OSS_ACCESS_KEY_ID` | 阿里云 OSS AccessKey ID | `<your-access-key-id>` |
| `ALIYUN_OSS_ACCESS_KEY_SECRET` | 阿里云 OSS AccessKey Secret | `<your-access-key-secret>` |
| `WECHAT_APPID` | 微信小程序 AppID | `wx********` |
| `WECHAT_APPSECRET` | 微信小程序 AppSecret（公开仓库前必须轮换，见下） | `<your-app-secret>` |
| `JWT_ADMIN_SECRET` | 管理端 JWT 签名密钥（代码内默认 `dev-only-admin-secret-change-me`，生产必须替换） | 随机长串 |
| `JWT_USER_SECRET` | 用户端 JWT 签名密钥（默认 `dev-only-user-secret-change-me`，生产必须替换） | 随机长串 |

### 2. 中间件与业务配置（有本地默认值，按需覆盖）

| 变量名 | 说明 | 默认值 |
| --- | --- | --- |
| `NACOS_SERVER_ADDR` | Nacos 注册/配置中心地址 | `127.0.0.1:8848` |
| `NACOS_USERNAME` / `NACOS_PASSWORD` | Nacos 鉴权账号 | `nacos` / `nacos` |
| `MYSQL_USERNAME` / `MYSQL_PASSWORD` | MySQL 账号（库 `ysd_take_out`） | `root` / `root` |
| `REDIS_HOST` / `REDIS_PORT` | Redis 地址 | `localhost` / `6379` |
| `REDIS_DATABASE` | Redis 库号：**业务缓存用 `10`**；`ysd-ai-service` 的向量库**单独用 `0`** | 见各 `application.yml` |
| `RABBITMQ_HOST` / `RABBITMQ_PORT` / `RABBITMQ_USERNAME` / `RABBITMQ_PASSWORD` | RabbitMQ 连接（`ysd-push-service`） | `localhost` / `5672` / `guest` / `guest` |
| `OLLAMA_BASE_URL` | Ollama embedding 服务地址（`bge-m3`，1024 维） | `http://127.0.0.1:18434`（注意不是默认 11434） |
| `NOTIFY_BASE_URL` | 微信支付回调对外基址 | `http://localhost:8085` |
| `ALIYUN_OSS_BUCKET` | OSS Bucket 名 | 空 |

### 3. 仅 `docker-compose.yml` 使用（`.env` 中提供）

| 变量名 | 说明 | 默认值 |
| --- | --- | --- |
| `NACOS_AUTH_TOKEN` | Nacos 鉴权 Token（必填） | 无（`?set ... in .env`） |
| `NACOS_ADMIN_PASSWORD` | Nacos 控制台 admin 密码（必填） | 无 |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码（必填） | 无 |
| `NACOS_AUTH_IDENTITY_KEY` / `NACOS_AUTH_IDENTITY_VALUE` | Nacos 服务端身份标识 | `serverIdentity` / `security` |
| `MAVEN_IMAGE` / `JRE_IMAGE` / `REDIS_IMAGE` | 构建/运行镜像覆盖 | `maven:3.9-eclipse-temurin-21` / `eclipse-temurin:21-jre` / `redis/redis-stack-server:latest` |

对应配置文件中的引用位置：

- OSS：`ysd-admin-service/src/main/resources/application.yml`（`ysd.alioss.*`）
- AI：`ysd-ai-service/src/main/resources/application.yml`（`spring.ai.openai.api-key` ← `DEEPSEEK_API_KEY`；`spring.ai.ollama.base-url` ← `OLLAMA_BASE_URL`；`spring.data.redis.database` = `0`）
- Nacos / MySQL / Redis / RabbitMQ：各服务 `application.yml`
- JWT：`ysd-gateway`、`ysd-admin-service`、`ysd-catalog-service`、`ysd-order-service`、`ysd-report-service`、`ysd-user-service` 的 `ysd.jwt.*`
- 微信：`ysd-user-service`、`ysd-order-service`
- 容器编排：仓库根 `docker-compose.yml`

> `ysd-server` 已下线，原 `ysd-server/src/main/resources/application-dev.yml` 引用作废；OSS 配置参考 `ysd-admin-service`。

该处配置为：

```yaml
access-key-id: ${ALIYUN_OSS_ACCESS_KEY_ID:}
access-key-secret: ${ALIYUN_OSS_ACCESS_KEY_SECRET:}
```

`:` 后面的空值为默认值，即**未设置时按空字符串处理**。

## 各环境设置方式

### 1. IDE（IntelliJ IDEA）

**方式 A：运行配置（单次生效）**

`Run` → `Edit Configurations...` → 选中对应启动类 → `Environment variables` 填入：

```
ALIYUN_OSS_ACCESS_KEY_ID=<your-access-key-id>;ALIYUN_OSS_ACCESS_KEY_SECRET=<your-access-key-secret>
```

**方式 B：全局环境变量（推荐，避免每个 Run Configuration 重复填）**

`Settings` → `Build, Execution, Deployment` → `Build Tools` → `Maven` → `Runner` → `Environment variables`，或在系统层面设置用户环境变量后重启 IDE。

### 2. Docker

`docker run`：

```bash
docker run -e ALIYUN_OSS_ACCESS_KEY_ID=<your-access-key-id> \
           -e ALIYUN_OSS_ACCESS_KEY_SECRET=<your-access-key-secret> \
           <image>
```

`docker-compose.yml`：

```yaml
services:
  ysd-admin-service:
    environment:
      - ALIYUN_OSS_ACCESS_KEY_ID=<your-access-key-id>
      - ALIYUN_OSS_ACCESS_KEY_SECRET=<your-access-key-secret>
```

> 生产环境建议改用 Docker secrets 或挂载文件方式注入，避免密钥出现在 compose 文件与 `docker inspect` 输出里。

### 3. 命令行 / Shell

**Linux / macOS（当前会话）：**

```bash
export ALIYUN_OSS_ACCESS_KEY_ID=<your-access-key-id>
export ALIYUN_OSS_ACCESS_KEY_SECRET=<your-access-key-secret>
```

**Windows PowerShell（当前会话）：**

```powershell
$env:ALIYUN_OSS_ACCESS_KEY_ID="<your-access-key-id>"
$env:ALIYUN_OSS_ACCESS_KEY_SECRET="<your-access-key-secret>"
```

**Windows CMD（当前会话）：**

```cmd
set ALIYUN_OSS_ACCESS_KEY_ID=<your-access-key-id>
set ALIYUN_OSS_ACCESS_KEY_SECRET=<your-access-key-secret>
```

## 本地测试注意事项

OSS 相关代码**不会在启动阶段校验密钥**：

- `OssConfiguration` 创建 `AliOssUtil` 时只是把配置值传入构造函数，**不会创建 OSS 客户端**。
- 真正的 `OSSClientBuilder().build(...)` 调用发生在 `AliOssUtil#upload(...)` 内部，即**首次调用上传接口时**。

因此：

- **不设环境变量，应用仍能正常启动**（配置项解析为空字符串，不会抛异常）。
- **但调用 `/admin/common/upload` 上传接口会失败**（空 Key 导致 OSS 鉴权错误，异常被 `upload()` 内的 try/catch 捕获并打日志）。

结论：**本地要联调上传功能时，必须先临时设置上面两个环境变量**（用 Shell `export` / IDE 运行配置即可）。仅做启动、编译等不涉及上传的验证时可以不设。

> 现有代码在 Key 为空时没有前置校验，失败信息会以日志形式出现，接口仍会返回一个拼接出来的 URL 字符串。后续如需更友好的提示，可考虑在上传入口增加空值校验（本次改动未涉及，仅作记录）。
