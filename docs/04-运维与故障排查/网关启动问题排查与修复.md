# YSD-gateway 无法启动 · 排查与修复文档

> ⚠️ **归档说明**：本文记录于微服务改造前期（2026-10）。部分方案已被后续架构取代，相关最新实现请参阅 `docs/02-架构设计与开发/` 或对应执行记录。

> 排查对象：`YSD-gateway/src/main/java/com/ysd/ysdgateway/YsdGatewayApplication.java`
> 基线：`ysd-take-out` master / Spring Boot **3.5.16** / JDK **21**（见 `pom.xml:9,22`）
> 结论：**网关当前连编译都进不去**，共 1 个阻塞性问题 + 3 个「修完仍会失败」的后续问题。

---

## 一、结论速览（TL;DR）

| 序号 | 现象层 | 问题 | 位置 | 严重度 |
|---|---|---|---|---|
| P1 | **构建期（阻塞）** | 3 个 Spring Cloud 依赖**未声明版本**，父 pom 无权管理其版本 | `YSD-gateway/pom.xml:44,49,53` | 🔴 致命 |
| P2 | 构建期 | 父工程用 Boot **4.1.1**，与项目基线 3.5.16 / SCA 2025.0.0.0 不匹配 | `YSD-gateway/pom.xml:8` | 🟠 高 |
| P3 | 编译期 | `@EnableDiscoveryClient` **缺少 import**，编译不通过 | `YsdGatewayApplication.java:7` | 🔴 致命 |
| P4 | 运行期 | Nacos `server-addr` 写成 **8858（控制台端口）**，应为 8848 | `YSD-gateway/.../application.yaml:10` | 🟠 高 |

**一句话根因**：网关 `pom.xml` 把自己挂在了 `spring-boot-starter-parent` 下，却使用 Spring Cloud 依赖 —— 而 **Spring Boot 的 BOM 从不管理 Spring Cloud 构件版本**，又没有 `dependencyManagement` 导入 SC / SCA 的 BOM，于是 Maven 在「读取 POM」阶段就报错退出，根本走不到启动。

## 二、可执行证据

在 `YSD-gateway/` 下执行（离线可复现）：

```bash
mvn -o -B validate
```

实际输出：

```
[ERROR] Some problems were encountered while processing the POMs:
[ERROR] 'dependencies.dependency.version' for org.springframework.cloud:spring-cloud-starter-gateway-server-webflux:jar is missing. @ line 44, column 21
[ERROR] 'dependencies.dependency.version' for com.alibaba.cloud:spring-cloud-starter-alibaba-nacos-discovery:jar is missing. @ line 49, column 21
[ERROR] 'dependencies.dependency.version' for org.springframework.cloud:spring-cloud-commons:jar is missing. @ line 53, column 21
[ERROR] The build could not read 1 project -> [Help 1]
```

旁证：`YSD-gateway/target/classes/` 下**只有 `application.yaml`，没有任何 `.class`** —— 说明该模块从未编译成功过。

本地仓库（`<maven-home>\maven-repository`）实际可用的版本组合：

| 构件 | 仓库内已有版本 |
|---|---|
| `spring-boot-starter-parent` | 3.5.16、**4.0.x、4.1.1** |
| `spring-cloud-dependencies` | **2025.0.0**、2025.1.1、2025.1.3 |
| `spring-cloud-alibaba-dependencies` | **2025.0.0.0** |
| `spring-cloud-starter-gateway-server-webflux` | **4.3.0**（仅此一个） |
| `spring-cloud-commons` | 4.3.0、5.0.3 |
| `nacos-client` | 3.0.3 |

即：**SC 2025.0.0 / SCA 2025.0.0.0 / Gateway 4.3.0 对应 Boot 3.5.x**；Boot 4.x 需要 SC 2025.1.x，而本地**并未下载 Gateway 5.0.x 的 starter**，方向本身就选错了。

## 三、根因逐条分析

### P1（致命）Spring Cloud 依赖没有版本，且父 pom 管不了

`YSD-gateway/pom.xml`：

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.1</version>
    <relativePath/>          <!-- 注意：不指向仓库根 pom，而是去远端找 Boot 父 -->
</parent>
...
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway-server-webflux</artifactId>   <!-- 无 <version> -->
</dependency>
```

`spring-boot-starter-parent` / `spring-boot-dependencies` 的作用域**只覆盖 Spring Boot 自家构件**，对 `org.springframework.cloud:*`、`com.alibaba.cloud:*` 一律不管。当前工程既没有注释里说的 BOM 导入，也没继承 `ysd-take-out` 根 pom（根 pom 才有 SC/SCA BOM，见 `pom.xml:136-150`），所以 Maven 找不到版本 → 直接拒绝读取 POM。

> 补充：`spring-cloud-commons` 这一条是**多余声明**。它已被 `spring-cloud-starter-gateway-server-webflux` 和 `nacos-discovery` 传递引入，删掉即可。

### P2（高）父子版本错配

| | 网关现状 | 项目其余模块 | 结论 |
|---|---|---|---|
| Spring Boot | 4.1.1 | 3.5.16（`pom.xml:9`） | 不一致 |
| 对应 Spring Cloud | 需 2025.1.x | 2025.0.0（`pom.xml:139`） | 不一致 |
| Spring Cloud Alibaba | 2025.0.0.0 | 2025.0.0.0 | 一致，但 **SCA 2025.0.0.0 的父是 `spring-cloud-dependencies-parent:4.3.0`**，即它只对齐 SC 2025.0 / Boot 3.5.x |

一个工程里两个 Boot 大版本，即使强行让它跑起来，Feign / LoadBalancer / Nacos 客户端也会和 `ysd-server` 出现协议与序列化层面的隐性错配。**必须统一到 Boot 3.5.16 + SC 2025.0.0 + SCA 2025.0.0.0**（与 `docs/02-架构设计与开发/微服务改造方案.md` §2.1 的推荐组合一致）。

### P3（致命）`@EnableDiscoveryClient` 未导入

`YsdGatewayApplication.java` 只有两个 import：

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
...
@EnableDiscoveryClient          // ← 没有对应 import，编译报 cannot find symbol
```

该注解全限定名为 `org.springframework.cloud.client.discovery.EnableDiscoveryClient`，位于 `spring-cloud-commons`（已验证 4.3.0 jar 内存在该类）。修好 P1/P2 后，编译会卡在这里。

> 注：Spring Cloud 2020+ 起，只要 classpath 上有注册中心 starter，自动装配即可完成注册，`@EnableDiscoveryClient` **非必需**。保留它是为了与 `ysd-server` 的启动类写法保持一致（`docs/02-架构设计与开发/微服务改造操作手册.md` 阶段 0 明确要求加）。

### P4（高）Nacos 地址写成了控制台端口

```yaml
# YSD-gateway/src/main/resources/application.yaml:10
server-addr: 127.0.0.1:8858      # ← 8858 是 Nacos 控制台端口
```

```yaml
# ysd-server/src/main/resources/application.yml:20
server-addr: 127.0.0.1:8848      # ← 8848 才是注册/发现的服务端口
```

手册阶段 0 验收写得很清楚：**「启动 Nacos（8848），控制台 8858」**（`docs/02-架构设计与开发/微服务改造操作手册.md:249`）。客户端注册与 `lb://` 服务发现必须连 **8848**；写成 8858 会连不上注册中心，网关里的 `lb://ysd-server` 永远解析不到实例。

## 四、修复步骤（推荐方案 A：网关并入父工程）

> 方案 A 与手册「父 pom 统一加 SC/SCA BOM」的既定路线一致，版本只有**一个来源**，后续拆服务时新模块照抄即可。

### 步骤 1 · 根 pom 声明网关为子模块

`<repo-root>\pom.xml`，`<modules>` 增加一行：

```xml
<modules>
    <module>ysd-common</module>
    <module>ysd-pojo</module>
    <module>ysd-server</module>
    <module>YSD-gateway</module>   <!-- 新增 -->
</modules>
```

### 步骤 2 · 重写网关 pom 头部与依赖

`<repo-root>\YSD-gateway\pom.xml`，把 `<parent>` 到 `</properties>` 一段替换为：

```xml
<parent>
    <groupId>com.ysd</groupId>
    <artifactId>ysd-take-out</artifactId>
    <version>1.0-SNAPSHOT</version>
    <relativePath>../pom.xml</relativePath>
</parent>

<groupId>com.ysd</groupId>
<artifactId>ysd-gateway</artifactId>
<version>1.0-SNAPSHOT</version>
<name>YSD-gateway</name>
<description>YSD-gateway</description>
<!-- java.version=21、SC/SCA 版本均从父 pom 继承，此处不再重复声明 -->
```

依赖段收敛为两条（**不写 `<version>`**，由父 pom 的 `dependencyManagement` 统一管理）：

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-starter-gateway-server-webflux</artifactId>
    </dependency>

    <dependency>
        <groupId>com.alibaba.cloud</groupId>
        <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
```

> - 删除原来的 `spring-cloud-commons` 显式依赖（传递即有）。
> - 删除原来的 `spring-boot-starter`：WebFlux starter 已包含所需 Boot 基础。
> - **不要**引入 `spring-boot-starter-web`：网关基于 WebFlux/reactor-netty，混入 Servlet 栈会让 Gateway 无法装配。

### 步骤 3 · 启动类补 import

`<repo-root>\YSD-gateway\src\main\java\com\ysd\ysdgateway\YsdGatewayApplication.java`：

```java
package com.ysd.ysdgateway;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.client.discovery.EnableDiscoveryClient;   // 新增

@SpringBootApplication
@EnableDiscoveryClient
public class YsdGatewayApplication {

    public static void main(String[] args) {
        SpringApplication.run(YsdGatewayApplication.class, args);
    }
}
```

### 步骤 4 · 修正 Nacos 地址

`<repo-root>\YSD-gateway\src\main\resources\application.yaml`：

```yaml
server:
  port: 9000

spring:
  application:
    name: ysd-gateway
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848     # ← 8848（服务端口），不是 8858（控制台端口）
        ip: 127.0.0.1
        username: nacos
        password: ${NACOS_PASSWORD:nacos}
    gateway:
      server:
        webflux:
          routes:                        # 该前缀是 Gateway 4.3+/5.x 的新写法，保持不变
            - id: ysd-server
              uri: lb://ysd-server       # 与 ysd-server 的 spring.application.name 一致
              predicates:
                - Path=/**
```

## 五、修改后验证

```bash
# 1) 先在根目录确认整个多模块能读取 POM（不再有 version is missing）
mvn -o -B validate

# 2) 编译网关（此时应能通过 P3）
mvn -o -B -pl YSD-gateway -am clean package -DskipTests

# 3) 确认 target/classes 下出现 .class（此前只有 yaml）
ls YSD-gateway/target/classes/com/ysd/ysdgateway/

# 4) 前置：Nacos 已在 8848 运行，ysd-server(8080) 已注册
#    启动网关
mvn -o -B -pl YSD-gateway spring-boot:run
```

期望结果：

| 验收点 | 期望 |
|---|---|
| 启动日志 | 出现 `Netty started on port 9000`，无 `MissingDependency` / `POM` 报错 |
| Nacos 控制台 :8858 | 「服务列表」出现 **ysd-gateway** 与 **ysd-server** 两个实例 |
| 路由转发 | `curl http://127.0.0.1:9000/admin/employee/login` 能透传到 8080 并返回业务响应 |

## 六、备选方案 B（坚持网关独立工程，不并入父 pom）

若不希望把 `YSD-gateway` 并入 `ysd-take-out`，则把它当作独立工程，但**版本必须自己管**：

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.5.16</version>       <!-- 由 4.1.1 改为与项目基线一致 -->
    <relativePath/>
</parent>

<properties>
    <java.version>21</java.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-dependencies</artifactId>
            <version>2025.0.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>com.alibaba.cloud</groupId>
            <artifactId>spring-cloud-alibaba-dependencies</artifactId>
            <version>2025.0.0.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

依赖列表、启动类 import（步骤 3）、yaml（步骤 4）与方案 A 完全相同。

**方案 B 的代价**：版本要在根 pom 与网关 pom 两处手工同步，后续拆 `ysd-user-service` 等新模块时会重复踩坑。**不推荐**，除非网关未来要独立仓库/独立发布节奏。

## 七、遗留注意点（通往阶段 1）

1. **缺少统一鉴权**：当前网关只做转发，`AuthGlobalFilter` 尚未编写。手册把这一步列为「必须自己写」的核心项（`docs/02-架构设计与开发/微服务改造操作手册.md` 阶段 1）。在此之前，`ysd-server` 的 `JwtTokenAdminInterceptor` / `JwtTokenUserInterceptor` 应暂时保留，形成双保险。
2. **`Path=/**` 过于粗暴**：现在把全部请求都打到 `ysd-server`。进入阶段 2 拆服务时，需按手册 §5 细化成 `/admin/employee/**` → `lb://ysd-admin-service` 之类的精确路由。
3. **Boot 4 相关依赖请勿回引**：本地仓库里同时存在 Boot 4.1.1 / SC 2025.1.x，容易误选。以根 pom 的 `2025.0.0` / `2025.0.0.0` 为准。
4. **`ip: 127.0.0.1` 不能省**：否则注册成 WSL 虚拟网卡地址，网关 `lb://` 转发必然失败（手册阶段 0 已强调）。
