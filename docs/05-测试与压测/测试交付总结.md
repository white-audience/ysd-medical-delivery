## 1. 一句话结论

**代码勘察发现：简历 14 条技术点中，7 条在本仓库没有任何实现痕迹**
（4 Redisson Lua 库存扣减、5 库存一致性、6 防超卖、8 延迟双删、9 缓存三防、10 SQL 优化、11 线程池）。
其余 7 条有实现，但其中 5 条存在**真实缺陷**（下单无事务、ThreadLocal 泄漏、状态机可非法回退、
缓存无 TTL、营业状态接口 NPE）。

**测试交付：16 个测试类 + 78 个用例**，全部可运行、可复现。
其中 **54 个用例通过**（覆盖真实可用的功能），**14 个用例失败**，**10 个用例跳过**（`@Disabled` 骨架）——
这 14 个失败**是设计意图**，每一个都是一条缺陷的可执行证据，精确指向 `docs/09-项目记录/修复与审计/代码问题清单.md`。

> 没有任何一个测试是为了「让简历好看」而写的。所有断言都针对真实代码或明确标注为
> `@Disabled` 的验收标准骨架，不存在「只有 `assertNotNull` 的无效测试」，
> 也不存在「mock 掉 Redis 来做并发测试」的假并发。

## 4. 如何运行

### 4.1 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| JDK | **21** | 2026-09-29 起工程为 Java 21 + Spring Boot 3.5.16，直接用本机 JDK 21 即可，**不再需要覆盖 `JAVA_HOME`** |
| Maven | 3.6+ | 无需 `mvnw`（仓库没有） |
| 网络 | 首次构建需要 | 需下载 `h2`、`embedded-redis:1.4.3`（约 12MB，内置 Windows redis-server 二进制） |
| MySQL | **不需要** | 用 H2 `MODE=MySQL` 内存库替代 |
| Redis | **不需要** | 测试自动启动真实 `redis-server` 进程（端口 16379） |
| Docker | **不需要** | Testcontainers 未使用（本机 Docker 不可用） |

### 4.2 命令

```bash
# 首次：把 ysd-common / ysd-pojo 装进本地仓库（ysd-server 依赖它们）
mvn -q install -DskipTests

# 【推荐·日常回归】只跑能通过的用例
mvn -pl ysd-server test -DexcludedGroups=bug-evidence
# 注意：该命令仍会带上 com.ysd.test 下两个既有坏类（HttpClientTest 2 error +
# SpringDateRedisTest 7 error，见 §5.4），要完全 0 error 需再用 -Dtest 排除它们

# 【缺陷验证】带上「缺陷证据」一起跑，会看到 14 个失败，每个都指向 bugs-found.md
mvn -pl ysd-server test
```

只跑新增的 16 个类（排除仓库里两个既有的坏测试类）：

```bash
mvn -pl ysd-server test \
  -Dtest='com.ysd.auth.**,com.ysd.cache.**,com.ysd.order.**,com.ysd.sql.**,com.ysd.stock.**,com.ysd.pool.**,com.ysd.engineering.**' \
  -DexcludedGroups=bug-evidence
```

> ⚠️ `-DexcludedGroups` 需要测试类路径上有测试引擎，`ysd-common` 没有测试依赖，
> 所以不能对 ysd-common 加该参数（用 `-pl ysd-server` 单模块跑，或先 `install`）。

只跑单个类 / 单个方法：

```bash
mvn -pl ysd-server test -Dtest=OrderTaskTest
mvn -pl ysd-server test -Dtest=CacheConcurrencyTest#热点key失效瞬间并发查询_无互斥时db被多次查询
```

> ⚠ Windows 下中文方法名在命令行里可能因编码问题匹配不上，建议优先用 `-Dtest=类名`。

### 4.3 关于 `bug-evidence` 标签

所有「断言简历声称行为、但当前实现做不到」的用例都打了 `@Tag("bug-evidence")`。
所以：

- `-DexcludedGroups=bug-evidence` → **全绿**，适合日常回归与 CI；
- 不带该参数 → 出现 **14 个失败**，这是**预期行为**，是缺陷的活证据，不要「修测试」，要修代码。

缺陷修复后，把对应用例的 `@Tag("bug-evidence")` 去掉即可纳入回归。
