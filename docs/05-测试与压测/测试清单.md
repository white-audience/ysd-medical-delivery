## 测试类型定义（本文档限定 5 种）

| 类型 | 含义 |
|---|---|
| 单元测试 | 不启动 Spring 容器或仅用 `@ExtendWith(MockitoExtension.class)`，依赖全部 mock |
| MockMvc 集成测试 | `@SpringBootTest + @AutoConfigureMockMvc`，走完整 Servlet 链路（含拦截器、异常处理器） |
| 并发测试 | `CountDownLatch` + `ExecutorService`，多线程竞争，必须真实中间件 |
| 故障注入测试 | 人为抛异常 / 篡改依赖，验证回滚、回补、降级 |
| SQL 验证 | 用 `JdbcTemplate` / `@Sql` 对真实库执行 DDL / EXPLAIN / 计数校验 |

## 优先级定义

| 级别 | 含义 |
|---|---|
| P0 | 核心链路，失败即不可上线 |
| P1 | 重要能力，影响数据正确性或可用性 |
| P2 | 补充覆盖，边界与文档完整性 |

## 重要前置说明

技术点 **4、5、6、8、11** 在仓库中**无对应实现代码**（见 `resume-project-audit.md`）。
按用户决定，这些技术点的测试类**照常生成**，但标注 `@Disabled` 并写明原因，
不做「假通过」。其用例在表中标记为 **【骨架】**。

技术点 **3、7、9、10** 属于「有代码但不满足简历声明」，测试分为两类：
- 断言**当前真实行为**的用例（会通过，用于记录差距）；
- 断言**简历声称行为**的用例，标注 `@Tag("bug-evidence")`——它们会**失败**，是把
  「声称」和「实际」的差距固化成可执行证据。

### 关于 `bug-evidence` 分组（重要）

所有「断言简历声称行为、但当前实现做不到」的用例统一打上 `@Tag("bug-evidence")` 标签。
因此有两套运行方式：

```bash
# 1) 只跑能通过的用例（全绿，用于日常回归 / CI）
mvn -pl ysd-server test -DexcludedGroups=bug-evidence

# 2) 带上「缺陷证据」一起跑（会看到 14 个失败，每个都指向 docs/09-项目记录/修复与审计/代码问题清单.md 里的一条缺陷）
mvn -pl ysd-server test
```

这些失败**不是测试写错了**，而是被测代码确实不满足简历声明。
在修复对应缺陷（见 `docs/09-项目记录/修复与审计/代码问题清单.md`）之前，它们应当保持失败。

## 预期失败用例（`@Tag("bug-evidence")`，共 14 条）

这些失败**是设计意图**：它们把「简历声称」与「代码实际」的差距固化成可执行证据。

| 用例ID | 失败原因 | 对应缺陷 |
|---|---|---|
| JWT-15、JWT-16 | 拦截器未实现 `afterCompletion`，ThreadLocal 不清理 | BUG-1 |
| JWT-11b | 营业状态未初始化时对 null 拆箱 → NPE 500 | BUG-8 |
| ORD-16、ORD-17 | `submitOrder` 误用 `java.beans.Transient`，无事务 | BUG-2 |
| ORD-09、ORD-10 | `confirm` / `cancel` 缺前置状态校验，状态机可回退 | BUG-4 |
| ORD-11 | `payment` 不校验订单状态，可重复支付 | BUG-5 |
| SQL-04、SQL-05 | 仓库无任何索引 DDL，`status` / `order_time` 无索引 | BUG-6 |
| CAC-03、CAC-04 | 药品 / 药品组合缓存均无 TTL（TTL = -1） | BUG-7 |
| CAC-05 | 无空值缓存，查不存在的 key 每次都穿透到 DB | BUG-7 |
| CAC-07 | 无 TTL 随机化，100 个 key 只有 1 种 TTL | BUG-7 |

`@Disabled` 用例（STK-01~09b、POOL-01~04、CAC-06、CAC-09、CAC-11、TASK-09）**不会执行**，

`CAC-10`、`CAC-11` 位于整体 `@Disabled` 的 `DelayDoubleDeleteTest` 中。
